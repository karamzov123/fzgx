## line__.bin pipeline

`files/enemy_line/line__.bin` (1,038,355 bytes) → `tools/linecrypt.py` (INT) →
`main.rel.lz` → `tools/avlz.py d` → `main.rel` (2,221,812 bytes).

- Cipher confirmed from `fze.sample.rel` disassembly (capstone on `.text` at
  file offset 0xBC): a 32-bit LCG `s = s*0x9B36BB94 + 0x000CD8F3`, seeded
  `s0 = 0xAF8910BE` (derived in the stub as `-(0x2C9E26E + 0x611B*0xCDDA - 0x68432A)`),
  XORed against each big-endian word. The 64-bit `mulhwu`/salt (`0x180A`) chain in
  the loop is dead code. Encrypt == decrypt. Round-trip byte-exact: yes.
- LZ: FF7-style LZSS, 8-byte LE header (payload size excl. header, uncompressed
  size), ring 0x1000 starting at 0xFEE, flag bit set = literal. Decoder mirrors
  the stub's routine at `.text+0x444`. Header: comp 1,038,347 (+8 = file size),
  uncomp 2,221,812. Decoded size matches header.
- Our greedy compressor produces 1,037,997 bytes (358 fewer than Sega's) that
  decode back to the identical main.rel. **Does not reproduce the original
  bytes.** Only `ninja disc` (runnable disc for the deferred shift test) needs
  that; matching targets the decompressed main.rel.
- Path obfuscation: the stub builds `enemy_line/line__.bin` from a 5-byte
  `.section4` at file offset 0x7F8 (the 4-letter word + NUL) with XOR/add
  patching at `.text+0x8C..0x13C`. Irrelevant to the build.

## Notes for M1

- `dtk dol info` / `dtk rel merge` on main.dol stall with "Overlapping
  functions 1:0x8006D1C4-1:0x8006D21C" — a jump-table region. The existing
  GFZE01 project works around it with `skip_cfa_ranges: .text:0x8006D000-0x8006E200`;
  we will need the equivalent in `config/GFZE01/config.yml`.
- All fifteen RELs must be configured as `modules:` so cross-module relocations
  resolve; `links:` may be needed if module ids are only unique per link set
  (ids are globally unique here, so the default should work).
