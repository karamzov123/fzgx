## Toolchain verified on this machine (Apple M4 Max, macOS 26.3)

- dtk v1.8.3 (`dtk-macos-arm64`), objdiff-cli v3.8.1, wibo 1.2.0 (`wibo-macos`,
  x86_64 under Rosetta 2), compilers pack `compilers_20251118`, ninja (brew).
- MWCC smoke test through wibo: a one-function TU compiles in ~60 ms.
- Compiler/linker versions are still the template defaults (linker GC/1.3.2,
  Dolphin libs GC/1.2.5n, RELs GC/1.3.2) and are **unverified**: no C has been
  compiled against retail yet. The existing GFZE01 project settled on linker
  GC/1.3 with a per-unit mix of GC/1.2.5n and GC/1.3. M2/M3 decide this by
  compiling known SDK functions under each candidate and comparing with objdiff.

## Analysis fixes needed

1. DOL: `skip_cfa_ranges .text:0x8006D000-0x8006E200` (jump-table region that
   stalls function-boundary analysis with "Overlapping functions").
2. main.rel: dtk sized the object at `.data:0x3D580` as 0x60 bytes, merging a
   12-entry switch table (relocations to `.text+0xCBA24..0xCBAC8`) with the
   strings that follow it ("YOU LOSE!", "BOMB!", "CLEAR TIME"). On the second
   pass those strings were read as jump-table entries. Fixed by setting
   `lbl_1_data_3D580` to `size:0x30` in `config/GFZE01/main_rel/symbols.txt`.
   Expect more of these as splits are refined; the fix is always a symbol size.

## Notes

- The DOL's extab/extabindex are absent ("Failed to locate section @ 0x8008FEE4"
  warning); the game was built with C++ exceptions off, as the template's
  `-Cpp_exceptions off` assumes.
- `config.rel_empty_file = "rel/empty.c"` links RELs that have no configured
  units; every REL currently links from split objects only, so it is unused.
- `config.shift_jis` is enabled only for GFZJ01.
