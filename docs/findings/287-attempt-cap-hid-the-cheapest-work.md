# 287 -- the attempt cap was hiding the cheapest work in the project
#
# Measured 2026-10-04, over the >=99% band, with `fzgx shapecensus --words`:
#
#   * 18 functions sit at <=2 differing instruction words, ten of them at exactly 1.
#   * **All 18 are past `ATTEMPT_CAP` and therefore unreachable by `choose()`.**
#   * `sweep` cannot reach them either: the deterministic engine measured 0 matches from
#     40,208 candidates across this band (finding 282).
#
# So the fleet was spending its entire budget on virgin 1-2 KB work at a measured 12.1%
# conversion while 18 functions sat one instruction from a match, with no path to them.
#
# ## The cap is right in general and wrong here
#
# `ATTEMPT_CAP = 2` exists so that five families do not re-derive the same wrong body over and
# over. That reasoning is correct for a function whose source is wrong -- a third attempt from
# the same context produces the same wrong source. It does not apply to a function that is one
# instruction away: the next attempt is not a re-derivation, it is a single edit, and the edit
# is the same edit for every family. Finding 285 already says the residue here is one operand,
# and *which* operand is a per-function question -- a question a deterministic sweep answers by
# enumeration (0/40,208) and a model session answers by reading the diff.
#
# The cap was preventing exactly the owner the work needed.
#
# ## Fix
#
# `retry=` already bypasses the cap for near-misses, so the tier rides that existing mechanism
# rather than adding a dispatch path. `state/one_word_tier.json` is generated by
# `fzgx shapecensus --words`, not hand-written, so the list is a measurement a reviewer can
# re-derive. A missing file yields an empty set and the fleet behaves exactly as before --
# verified by removing the file and confirming identical picks.
#
# Three gate details each had to be fixed, and each was found by measuring rather than by
# reading, because none of them is wrong on its own:
#
#   1. **Family lockout emptied the tier.** Filtering the tier by `families_that_tried()` gave
#      0/6 for every family: they had all already run the tier symbols. Lockout exists to stop
#      wasted re-derivation, and a one-word function is not that. The tier is now exempt; the
#      atomic claim in `api.claim` already prevents two families holding one symbol.
#   2. **Ordering, not just eligibility.** With the tier merely *eligible*, `fresh + tierrows`
#      put it behind six virgin functions and it was never reached. The tier leads the list.
#   3. **Family size bands excluded 5 of the 18 outright** (they are mostly under 1 KB, and
#      cline's band is 1-2 KB). A band is a division of labour, not a quality gate, and cannot
#      be allowed to hide a one-word function. The tier is lifted above the band. All 18 pass
#      `size_allowed`, so the attempt cap remains the only real eligibility limit.
#
# After the fix, all five families pick 6/6 tier functions, every one of them past the cap.
# A rotation by family index (measured: without it five families proposed `fn_10_A90C` five
# times -- 30 slots, ~8 distinct functions) spread this to 13 distinct symbols per batch; the
# residual overlap is arithmetic, 30 slots for 18 functions, and refused claims are absorbed by
# the atomic claim.
#
# ## Correction to an earlier claim
#
# The first pass of this census reported `fn_10_1B2F4`, `fn_1_15EC40` and `fn_1_9DB04` as
# "0 words differing", which reads as finished. They are not: objdiff shows 32, 29 and 28
# flagged rows respectively, and the defect is a shared-pool binding --
# `lis r4, lbl_10_rodata_158@ha` against `lis r4, ...rodata.0@ha`. **A relocation difference
# does not move an instruction word, so any word-count-only metric reads this class as a
# match.** `word_diff` now reports `flagged_rows` next to `differing`, and `--words` prints
# both. This is the same trap as finding 286, one level deeper: 26 diff rows meant 1 word there;
# 0 words can still mean 32 rows here.
